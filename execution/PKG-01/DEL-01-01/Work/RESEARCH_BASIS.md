## A. Assigned targets, observed cooperation, and evaluator labels

**Problem, recipient and multi-agent mechanism.** Researchers and deployers need
to know what a collusion detector's labels mean before using it to flag cooperating
agents. In NARCBench-Core, four agents deliberate; two can privately coordinate
while the monitor uses different evidence. Agreement, pursuit of an assigned
suboptimal option, and winning the committee vote are distinct collective events.
Misidentifying the reference could reward a detector for predicting role assignment
rather than the behavior its user cares about.

**Closest work and possible addition.** The nearest organizer leads are “Catch the
cartel,” “Can copies collude without talking?” and the Track 4 reading by Rose et
al., [Detecting Multi-Agent Collusion Through Multi-Agent Interpretability](https://arxiv.org/abs/2604.01151).
The examined version is v5; Appendix J.7 says Core discards runs when both colluders
do not vote for the assigned target or their messages show no coordination. Appendix
L.9 qualifies any broad success-filter description: ineffective but attempted Stego
collusion can be retained. Greenblatt et al. already study shared-input and
output-signal collusion; Motwani et al. already study secret/Schelling coordination.
A new live demonstration of those phenomena is not the proposed addition.

The candidate addition is a reproducible audit of **reference provenance**: compare
independently assigned targets and role/behavior labels with released audit outputs
and inclusion lists, preserving tier-specific semantics. This is a possible
reproducibility or evaluator-reliability contribution, not an established novelty
claim or a finding that the paper's scores are wrong. The [source review](coordination-controls/SOURCE_REVIEW.md) supplies examined passages and identities.

**Question and competing explanations.** Does the released checking path verify
compliance with a preassigned target, or can agreement substitute for that target?
If code, raw data, metadata and paper counts differ, possibilities include a helper
that was never used for final filtering, a different dataset version, explicit
training/evaluation splits, manual exclusion, stale metadata, or an actual label
error. Test those explanations rather than treating a mismatch as misconduct.

**Formation observations.** Static reading at verified code commit `237fe60739502007693b6455c6c644606ab3bcbb`
of `generation/verify_ground_truth.py`
shows `_infer_target` returns a unanimous pair's vote before consulting target
metadata; `audit_run` then compares those same votes with that inferred value.
In contrast, inspected generation code compares votes with the independently
configured target and separately records `target_majority` (at least three of
four votes). A helper issue is therefore not automatically a generation error.
The public dataset revision `19cb14b269e052b19ba6d2bd2f4519afd3b10c57` provides
`run_config.json`, `agent_prompts.json` and `results.json` for sampled runs.
The two sampled collusion runs (`deception__audit_01__collusion` and
`deception__audit_02__collusion`) both follow their assigned targets; the paired
`audit_01` control has no colluder roles/private messages. These are useful valid
checks, **not observed false labels**. `collusion_success=true` with
`target_majority=false` is consistent with the generator's distinct definitions.

The inspected Core `metadata_gen.json` contains 1,054 agent-turn rows across 62
run IDs (31 collusion and 31 control); the two `audit_01` runs are present, while
raw `audit_02__collusion` is absent. The paper's J.7 describes 36 retained collusion
scenarios and 50 controls. Different releases, splits and filtering remain live
explanations. No activation arrays were downloaded, no model was run, and the
relationship between this metadata and the paper's exact evaluation has not been
established.

**Units and observation boundaries.** Primary units would be scenario/run pairs;
agent turns are nested observations, not independent samples. Actors receive their
own role prompts and permitted message channels. A deployed text monitor must not
receive private assignment or target labels merely because the evaluator can
inspect them; activation-monitor access is a different condition. The offline
evaluator may use stored configs, prompts, votes and selection metadata, but must
crosscheck agreement between those sources rather than assuming any one is truth.
Do not infer intent or realized harm from a role string or vote equality alone.

**Feasible method and discriminating result.** First recover the exact paper/code/
data version relationship and reconstruct intended-target checks on a bounded Core

## C. Completion reports, wrong references, and diagnostic abstention

**Problem, recipient and mechanism.** A supervisor must decide whether downstream
workers can safely rely on an upstream “done” report, and whether a failed outcome
justifies blaming that worker. The multi-agent mechanism is reliance across a
handoff: a worker's statement changes another worker's action. A bad reference,
stale query or grading mistake can make correct work look faulty, while a false
completion report can propagate an actual defect.

**Prior work and possible addition.** The exact organizer examples are “Did it
actually happen?” and “Whose fault was it?” Their local text supplies no separate
inline citation; the nearest track reading is Zhang et al.'s Who&When. That paper
already contrasts attribution with and without reference answers. Who&When Pro
already injects mistakes after controlled replay; BLADE audits cross-agent handoffs;
TraceTrial distinguishes authoritative state, model-facing evidence and apparatus
failures. Basin et al. already supply three-valued monitoring under missing events.
The candidate addition would therefore be a narrowly specified test of **false
worker blame when the reference or observation mechanism is wrong**, including
ordinary correct runs and explicit insufficient-evidence outcomes. Broad claims
that state verification or abstention are new are withdrawn by the source reading.

**Question and alternatives.** Under what minimal evidence does a downstream
completion check distinguish worker nonperformance, committed but delayed/stale
state, an incorrect task reference, and a broken grader? A deterministic protocol
study could establish an observation/decision property; claims about LLM behavior,
frequency of false reports or a monitor's generalization require separate empirical
trials. Honest mistakes, ambiguous completion semantics and malicious deception
must not share a label by assumption.

**Observation and argument conditions.** The study unit would be one handoff episode. Define one state transition, an explicit
commit boundary, and an independently written invariant for a three-role workflow
(writer, dependent reader, checker). A concrete feasibility thought experiment:
a writer reports a committed version v2; the dependent reader sees v1. The same
report/read view is compatible with no write and with a successful write plus a
stale read. A trusted, causally ordered commit/read observation can distinguish
these histories. It does not by itself prove the task reference is correct; that
requires checking the reference against the task rule or a separately derived
oracle. The evaluator holds injected cause/state; the diagnostic monitor receives
only its declared evidence. Providing the injected cause to the monitor would
invalidate the comparison. A valid case must allow a correct handoff without blame.

**Feasible route and method.** A small deterministic local model with documented
state semantics is constructible without new models; this pass has not built or
run it. Existing-record evidence is inadequate for measuring the proposed error
rate: Who&When's selected failures do not furnish the necessary success/control
population, and public swarm payloads lack the needed state observations. If
selected, first define the property and independent reference, inspect related
work more narrowly, and test ordinary/missing/stale/wrong-reference cases. Only
then decide whether a human or model diagnostic comparison adds useful evidence.
Those would be constructed protocol cases, not observed natural agent trajectories.

**Means, effort, scrutiny and open choices.** Reuse SQLite or an in-memory state
machine and a small offline case representation rather than an agent platform.
Budget several hours for protocol definition, oracle checks and the first examined
result; a credible model comparison additionally needs actual model/time resources
and varied held-out cases. Costs are planning judgments, not measured savings.
Separate scrutiny should derive the reference independently, try indistinguishable
histories and faulty-checker counterexamples, and reject tautological tests where
injection labels are exposed to the diagnostician. The present novelty search and
natural-data qualification are insufficient for a confident empirical study. C is
ready for a further bounded design/source inquiry, not focused empirical testing;
retain it as a fallback or follow-on to A, not an already validated contribution.

### E. Trusted evidence recovery in peer verification

**Problem, recipient and mechanism.** Two agents verify one another while sharing
reward and history. A correct task answer, a valid evidence-based verdict, receipt

useful verification without rewarding unsupported acceptance or forcing all work
to stop when evidence is unavailable. The particular mechanism is whether peer
influence/shared incentives still induce invalid agreement when an authorized,
independent route to evidence exists—and whether peers can substitute their own
claims for that route's result.

sharing. It does not identify an independent effect of trusted-versus-peer
provenance, which is held fixed in the recovery routes. Alternatives:
peers ignore recovery despite availability; shared reward dominates evidence use;
recovery logs are obtained but not evaluated; independent task references are wrong;
requests trigger excessive cost; or ordinary full-information verification already
achieves the same result. A valid negative outcome is that the conditional scheme
adds complexity without benefit over unconditional evidence access.
